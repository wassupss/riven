# 여러 모델이 목표를 도출하게 만들기 — 설계

목표: **여러 모델이 패널 간 소통을 통해 하나의 결론(목표)을 도출해내는 것.**
지금(v0.2.30 + 그룹 수정)까지 깔린 토대와, 그 위에 무엇을 더 얹어야 하는지.

## 지금 있는 것

- 패널 = 에이전트. id/이름으로 주소 지정, 그룹 로스터(워크스페이스 트리에 영속).
- `riven_ask_agent` — 패널당 **직렬화**, 답은 **그 질문의 턴**에 묶임, 순환 대기 즉시 거절.
- `riven_group_broadcast` — 그룹 전원에게 한 번에, 답을 모아서 반환.
- 그룹 타임라인 — 오간 말이 사용자에게 보임. 그룹 지시 입력창.
- Claude / Codex 혼합 가능(멤버마다 CLI·모델 지정).

## 무엇이 없어서 "도출"이 안 되는가

1. **누적되는 대상이 없다.** 모든 교환이 일회성 텍스트다. 라운드를 돌아도 남는 것은
   각자의 대화 로그뿐이고, 다음 라운드는 다시 처음부터 설명해야 한다.
2. **공유 맥락이 없다.** 멤버는 서로의 답을 못 본다. 리드가 일일이 전달해야 하는데,
   그 과정에서 요약되며 왜곡되고 토큰도 두 배로 든다.
3. **끝나는 조건이 없다.** 언제 끝났는지 아무도 판정하지 않는다. 에이전트끼리는
   서로 동의하며 무한히 라운드를 돌 수 있고, 비용은 라운드마다 멤버 수만큼 든다.
4. **결과물이 남지 않는다.** 최종 결론이 리드의 대화 안에 묻힌다.

## 설계: 목표판(goal board)

그룹에 **하나의 공유 객체**를 준다. 모든 멤버가 읽고 쓰는 게시판이고,
사용자는 패널에서 같은 것을 본다.

```ts
interface Goal {
  id: string
  ws: string
  group: string
  goal: string          // 도출하려는 것
  doneWhen: string      // 무엇이 충족되면 끝인지 (사람 말로)
  artifact?: string     // 결과를 남길 파일 경로 (선택)
  round: number
  status: 'open' | 'converged' | 'stopped'
  posts: Post[]
}

interface Post {
  id: string
  round: number
  by: string            // pane key
  kind: 'proposal' | 'critique' | 'revision' | 'vote' | 'note'
  text: string
  at: number
}
```

영속: 워크스페이스 트리(sessions.json). 활동 로그와 달리 목표는 **일**이므로 남아야 한다.
용량: post 텍스트 상한 + 오래된 라운드는 요약으로 접는다.

### 툴

| 툴 | 하는 일 |
| --- | --- |
| `riven_goal_start(group, goal, done_when, artifact?)` | 목표판 생성, id 반환 |
| `riven_goal_state(goal_id)` | 목표·라운드·모든 post(압축)·로스터 반환 — **멤버가 맥락을 읽는 유일한 통로** |
| `riven_goal_round(goal_id, ask, kind, exclude_author?)` | 한 라운드: 전원에게 `ask`를 보내고 답을 post로 자동 기록 |
| `riven_goal_post(goal_id, kind, text)` | 멤버가 스스로 올리는 글(라운드 밖) |
| `riven_goal_finish(goal_id, summary)` | 수렴 선언. artifact가 있으면 파일로 기록 |

`riven_goal_round`가 핵심이다. **한 번의 툴 호출 = 한 라운드**라서 리드가 몰기 쉽고,
사용자는 타임라인에서 라운드 단위로 읽을 수 있다. 라운드는 패널당 직렬화된 위임을
병렬로 돌리는 것이므로 이미 있는 경로를 그대로 쓴다.

### 라운드 진행

기본형(리드가 고른다, riven이 경계를 강제):

1. `proposal` — 전원이 각자 안을 낸다 (서로 안 보고, 편향 없이)
2. `critique` — 각자 **남의 안**을 본다(`exclude_author`), 반론·위험 지적
3. `revision` — 지적을 반영해 수정안
4. `vote` — 하나를 고르고 이유를 적는다
5. 리드가 `finish`로 수렴 선언, 또는 2로 돌아간다

모델을 섞을 때 2번이 특히 값을 한다: 다른 계열 모델이 서로의 맹점을 본다.

### 멈추는 장치

라운드 수 상한은 **두지 않는다**(결정 완료). 자동으로 끊기지 않는 대신, 사람이 끊을 수
있게 만드는 쪽에 무게를 싣는다 — 그러면 그것이 유일한 안전장치이므로 흐릿해서는 안 된다.

- **중단 버튼**: 목표 탭에 항상. 진행 중인 라운드의 턴까지 인터럽트하고 목표를 `stopped`로.
- **비용이 계속 보인다**: 목표마다 누적 라운드 수 · 턴 수 · 토큰을 탭과 타임라인에 표시.
  라운드를 시작할 때 "이 라운드 = 멤버 N명 × 1턴"을 타임라인에 먼저 남겨, 무엇을 쓰기
  직전인지 보이게 한다.
- **오래 돌면 눈에 띄게**: 탭에 경과 시간과 턴 수. 막지는 않되 숨기지도 않는다.

## 정해진 것

1. **수렴 판정 = 리드가 선언.** 투표 과반은 서로 동의하는 쪽으로 쏠리고, 사용자 승인은
   사람이 계속 붙어 있어야 한다. 사용자는 언제든 중단·개입할 수 있다.
2. **라운드 상한 없음.** (위 "멈추는 장치")
3. **결과물은 `artifact`를 지정한 목표만 파일로.** 자동 생성은 저장소를 어지럽힌다.
4. **사람도 목표판에 글을 올린다.** 방향이 틀어졌을 때 라운드 사이에 한 줄 넣는 것이
   가장 싸게 고치는 방법이다.

## 순서

1. 목표판 스토어 + 영속 + 순수 로직 테스트 (작음)
2. `goal_start` / `goal_state` / `goal_post` / `goal_finish` (작음)
3. `goal_round` — 라운드 실행, 자동 기록, 상한 (중간)
4. 패널의 목표 탭 — 라운드별 post, 중단 버튼, 사람 post (중간)
5. 실제로 3모델(Opus·Codex·Fable)로 한 목표를 돌려 보고 프롬프트 조정 (중간)
